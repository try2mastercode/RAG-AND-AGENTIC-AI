🔌 MCP Agent Toolkit

A Groq agent that never calls its own tools directly — every tool, resource and prompt below is served by a separate MCP server process, reached only over the real Model Context Protocol (JSON-RPC over stdio).

View raw API docs (Swagger UI) →

How this actually talks to the MCP server

Two separate processes, one protocol connecting them:

1

spawn + handshake

On startup the client launches mcp_server.py as a subprocess and speaks MCP over its stdin/stdout, then calls list_tools / list_resources / list_prompts to discover what's on offer.

→
2

schema pass-through

Every MCP tool's JSON Schema is handed to Groq as-is, as an OpenAI-style function tool def — no translation layer.

→
3

Groq decides

The model reads your message and either replies directly or returns one or more tool_calls naming an MCP tool and its arguments.

→
4

real MCP round trip

Each tool call becomes a session.call_tool() request sent over stdio to the server process, which runs the actual sqlite read/write and replies.

→
5

loop or answer

Tool results go back to Groq as role: "tool" messages; it can call more tools or stop, until it returns a plain answer.

What the client discovered from the server

Fetched once at page load via GET /protocol, which just forwards the MCP client's own list_tools/list_resources/list_prompts results — this is the server's real capability list, not a hardcoded description.
