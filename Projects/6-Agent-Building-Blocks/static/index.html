🧩 Agent Building Blocks

A project walking through how a LangChain agent is actually put together — tools, manual tool-calling, LCEL runnables, an orchestrating agent with memory, and two purpose-built agents (SQL, data visualization) — all running live against Groq.

What makes something a "tool"

Every panel below is one layer of the same idea, stacked:

1

Define a tool

A Python function gets a name, description, and JSON input schema — that's the whole contract the model sees.

→
2

Bind it to a model

bind_tools() hands those schemas to the LLM. The model can only ever request a call — it never executes anything itself.

→
3

A loop executes it

Code (or create_agent's built-in loop) runs the tool, feeds the result back, and asks the model again.

→
4

Specialize the loop

A SQL agent and a chart agent are the same loop — just pointed at different tools.

1. Tool creation, five ways

LangChain has several ways to turn a plain function into something a model can call. They all end up as the same shape: a name, a description, and a JSON args schema.
