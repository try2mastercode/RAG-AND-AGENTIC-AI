🥊 Multi-Agent Framework Showdown

The same idea — a researcher and a writer agent working together — built three different ways: CrewAI's sequential crew, AutoGen's round-robin team chat, and a BeeAI ReAct agent that reasons about when to call a tool.

View raw API docs (Swagger UI) →

Why this app runs three Python interpreters

CrewAI and BeeAI pin conflicting pydantic versions, and neither installs cleanly on this machine's default Python 3.14 — so each gets its own isolated venv, launched as a subprocess. AutoGen has no such conflict and runs in-process.

1

CrewAI

Subprocess in a Python 3.11 venv (crewai_runner.py). Talks back to the server over stdout as one line of JSON.

2

AutoGen

Runs directly inside this FastAPI process (autogen_lab.py) — no version conflict, no subprocess needed.

BeeAI

Its own separate Python 3.11 venv (beeai_runner.py) — a different one from CrewAI's, since the two can't share an interpreter either.

1. CrewAI sequential crew

Two Agents (role, goal, backstory) run as two Tasks in order — the writer's task declares context=[research_task], so it receives the researcher's output automatically. Process.sequential runs them one after another, no back-and-forth.
